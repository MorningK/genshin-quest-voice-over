# 原神任务语音助手 · 产品需求文档（PRD）

> **产品名称**：原神任务语音助手（Genshin Quest Voice Over）
> **文档版本**：v1.0
> **产品阶段**：MVP（Minimum Viable Product）
> **目标平台**：Windows 桌面端
> **文档日期**：2026-05-27

---

## 1. 产品概述

### 1.1 产品定位

原神任务语音助手是一款 Windows 桌面工具，旨在为《原神》中没有语音配音的任务（主要是世界任务）提供**实时的对话文本配音**服务。

### 1.2 产品愿景

让每一位《原神》玩家在大世界探索、完成支线任务时，都能享受到如同主线剧情般的完整配音体验。

### 1.3 核心价值

- **沉浸感提升**：将原本静默的世界任务对话赋予声音，提升游戏代入感
- **无障碍体验**：帮助视障玩家或阅读困难的玩家通过听觉接收任务信息
- **零侵入性**：不修改游戏客户端，仅通过图像识别和音频输出实现，安全合规

## 2. 用户分析与需求背景

### 2.1 目标用户

| 用户类型 | 特征描述 | 核心痛点 |
|---------|---------|---------|
| 剧情党玩家 | 重视游戏剧情和世界观，希望完整体验所有任务叙事 | 世界任务无配音，阅读长文本疲劳 |
| 休闲玩家 | 游戏时间有限，希望快速获取任务信息 | 大段对话文本阅读耗时 |
| 视障/弱视玩家 | 阅读屏幕文字存在困难 | 缺乏听觉替代方案 |
| 多任务玩家 | 一边做任务一边做其他事情（刷材料等） | 无法同时阅读对话文本 |

### 2.2 需求背景

- 《原神》中，**魔神任务（主线）** 和部分**传说任务**拥有全程语音配音
- **世界任务**、**每日委托**、**活动支线**等大量任务内容**无配音**
- 社区中长期存在"希望加入世界任务配音"的呼声，但官方尚未提供此功能
- 部分第三方 MOD 尝试过类似功能，但大多存在稳定性差、安全性存疑等问题

### 2.3 使用场景

```
小明正在完成一个长篇世界任务"森林书"，对话文本量巨大，
但由于没有配音，他需要逐句阅读字幕，阅读疲劳感强。
他打开原神任务语音助手，工具自动检测到对话界面，
实时朗读每一句对话，小明可以专注于游戏画面而无需盯着字幕。
```

## 3. 核心功能设计

### 3.1 功能架构总览

```
┌─────────────────────────────────────────────────┐
│                  控制层                          │
│         启动/停止   ·   全局快捷键   ·   托盘图标    │
├─────────────────────────────────────────────────┤
│                  处理层                          │
│   画面采集  →  文本识别  →  文本处理  →  语音合成   │
├─────────────────────────────────────────────────┤
│                  输出层                          │
│              音频播放（系统默认音频设备）             │
└─────────────────────────────────────────────────┘
```

### 3.2 功能模块详细说明

#### 3.2.1 画面采集模块

- **功能描述**：实时捕获《原神》游戏窗口的指定区域画面
- **MVP 要求**：
  - 支持自动检测原神游戏窗口并定位对话区域
  - 支持手动框选/调整识别区域
  - 以固定帧率（建议 2-4 FPS）进行画面截取，平衡性能与响应速度
- **技术要点**：使用 Windows 屏幕捕获 API（DXGI / Win32 GDI）实现低延迟截图

#### 3.2.2 OCR 文本识别模块

- **功能描述**：从捕获的画面中识别并提取对话文本
- **MVP 要求**：
  - 精准识别《原神》对话界面中的文字
  - 自动过滤非对话文本（如 UI 按钮、技能提示等）
  - 支持繁体中文和简体中文识别
- **文本处理规则**：
  - 去重：相同文本不重复播报
  - 去噪：过滤空白行、无意义符号
  - 分段：按自然停顿合理拆分长文本

#### 3.2.3 TTS 语音合成模块

- **功能描述**：将识别到的文本实时转换为自然语音
- **MVP 要求**：
  - 支持中文语音合成，音色自然流畅
  - 低延迟，从识别到开始播放控制在 1 秒以内
  - 支持离线 TTS，无需网络环境即可使用
- **候选方案**：
  - **Edge TTS**（在线）：免费、音质好，但依赖网络
  - **VITS / Bert-VITS2**（离线）：开源方案，可本地部署，音质可控

#### 3.2.4 音频播放模块

- **功能描述**：播放合成后的语音并管理播放队列
- **MVP 要求**：
  - 通过系统默认音频设备播放
  - 支持播放队列管理：上一句未播完时，新文本进入排队
  - 支持即时中断：新的对话出现时可中止当前播放
  - 音量可调节，默认与游戏音量协调

#### 3.2.5 控制与交互模块

- **功能描述**：提供用户对工具的控制入口
- **MVP 要求**：
  - **启动/停止**：一键开启或关闭配音服务
  - **全局快捷键**：通过快捷键快速控制（如 `Ctrl+Shift+V` 切换开关）
  - **系统托盘图标**：最小化到托盘运行，右键菜单提供退出选项
  - **状态提示**：托盘图标显示当前工作状态（运行中/暂停/异常）

## 4. 技术架构

### 4.1 整体架构图

```
┌──────────────────────────────────────────────────────────┐
│                      用户交互层                            │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐               │
│  │ 全局快捷键 │  │ 托盘图标  │  │ 设置界面  │               │
│  └──────────┘  └──────────┘  └──────────┘               │
├──────────────────────────────────────────────────────────┤
│                       业务逻辑层                           │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐ │
│  │ 窗口检测  │  │ OCR引擎  │  │ 文本处理  │  │ TTS引擎  │ │
│  └──────────┘  └──────────┘  └──────────┘  └──────────┘ │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐               │
│  │ 截图调度  │  │ 结果缓存  │  │ 播放队列  │               │
│  └──────────┘  └──────────┘  └──────────┘               │
├──────────────────────────────────────────────────────────┤
│                       系统依赖层                           │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐               │
│  │ 屏幕捕获  │  │ 音频输出  │  │ 本地存储  │               │
│  │ (DXGI)   │  │ (WASAPI) │  │ (SQLite) │               │
│  └──────────┘  └──────────┘  └──────────┘               │
└──────────────────────────────────────────────────────────┘
```

### 4.2 核心数据流

```
游戏运行 → 屏幕捕获（2-4 FPS）→ 图像预处理（二值化/裁剪）
    → OCR文本识别 → 文本去重/清洗
        → 文本变化检测（与上一句对比）
            ├── 无变化 → 丢弃
            └── 有变化 → 送入播放队列
                            → TTS语音合成 → 音频播放
```

### 4.3 技术选型

| 模块 | 技术方案 | 选型理由 |
|------|---------|---------|
| 开发语言 | Python 3.12+ | 生态丰富，OCR/TTS 库成熟，快速开发 MVP |
| GUI 框架 | PySide6 / PyQt6 | 跨 Windows 原生控件，托盘图标支持好 |
| 屏幕捕获 | DXCam / MSS | 低延迟截图，支持指定窗口区域 |
| OCR 引擎 | RapidOCR（默认）+ PaddleOCR（备选） | 离线可用、轻量部署；中文识别准确率高 |
| TTS 引擎 | Edge TTS（在线）+ VITS（离线备选） | MVP 优先用免费方案快速验证 |
| 音频播放 | PyAudio / simpleaudio | 简单易用，支持流式播放 |
| 打包工具 | PyInstaller / Nuitka | 将 Python 应用打包为独立 .exe |

### 4.4 打包与分发

- **打包格式**：使用 PyInstaller 将应用打包为单个 `GenshinVoiceOver.exe`
- **文件结构**：
  ```
  GenshinVoiceOver/
  ├── GenshinVoiceOver.exe    # 主程序
  ├── models/                 # OCR/TTS 模型文件
  ├── config.json             # 用户配置文件
  └── logs/                   # 运行日志
  ```
- **分发方式**：GitHub Releases 发布压缩包或安装器

## 5. MVP 范围定义

### 5.1 MVP 必须实现（Must Have）

| 序号 | 功能项 | 优先级 | 验收标准 |
|------|--------|--------|---------|
| 1 | 自动检测游戏窗口 | P0 | 启动后 3 秒内识别到原神窗口 |
| 2 | 对话区域定位 | P0 | 准确截取对话文字区域 |
| 3 | OCR 文本识别 | P0 | 中文识别准确率 ≥ 90% |
| 4 | 文本去重过滤 | P0 | 同一句对话不会重复播报两次 |
| 5 | TTS 语音合成 | P0 | 单句合成延迟 ≤ 1 秒 |
| 6 | 音频播放 | P0 | 声音清晰、无杂音、可正常播放 |
| 7 | 启动/停止控制 | P0 | 一键开关配音服务，响应时间 ≤ 1 秒 |
| 8 | 系统托盘运行 | P1 | 可最小化到托盘，不影响游戏 |
| 9 | 打包为 .exe | P0 | 双击即可运行，无需安装 Python 环境 |

### 5.2 MVP 暂不实现（Not Now）

| 功能项 | 说明 |
|--------|------|
| 多语言支持 | MVP 仅支持中文，后续扩展日/英/韩 |
| 自定义 TTS 音色 | MVP 使用单一默认音色 |
| 用户偏好设置界面 | MVP 通过配置文件手动修改 |
| 语音变速/音调调节 | 二期功能 |
| 支持其他游戏 | 仅支持《原神》 |
| 自动更新 | 手动下载更新 |
| 对话历史记录回放 | 二期功能 |

### 5.3 MVP 核心指标

| 指标 | 目标值 |
|------|--------|
| 首次启动到可用 | ≤ 30 秒 |
| OCR 识别准确率 | ≥ 90% |
| TTS 合成延迟 | ≤ 1 秒 |
| 端到端延迟（截图→播放） | ≤ 2 秒 |
| CPU 占用（运行时） | ≤ 20% |
| 内存占用 | ≤ 500 MB |
| 崩溃率 | ≤ 1 次/小时 |

## 6. 非功能需求

### 6.1 性能要求

- **低资源占用**：工具运行时不应显著影响游戏帧率
- **快响应**：从对话文本出现到开始播放语音，延迟控制在 2 秒以内
- **内存可控**：长时间运行（≥ 3 小时）不出现内存泄漏

### 6.2 兼容性要求

- 操作系统：Windows 10 1809+ / Windows 11
- 游戏版本：《原神》官方 PC 客户端最新版本
- 显示分辨率：1920×1080 及以上

### 6.3 安全性要求

- **不修改游戏客户端**：纯外部工具，通过图像识别运行
- **无数据收集**：不收集用户的游戏数据和个人信息
- **不做反作弊干扰**：不与游戏进程交互，避免被反作弊系统误判

### 6.4 稳定性要求

- 游戏窗口切换、最小化时工具能正常恢复
- 对话快速切换时不出现崩溃或播放混乱
- 网络断连时（在线 TTS 方案）有友好提示和降级策略

## 7. 风险与挑战

| 风险项 | 影响 | 缓解措施 |
|--------|------|---------|
| 反作弊误判 | 用户账号安全 | 仅读取屏幕画面，不注入游戏进程 |
| OCR 识别不准 | 用户体验差 | 使用 RapidOCR + 针对游戏字体的预处理优化，必要时切换 PaddleOCR |
| TTS 延迟过高 | 对话已过，语音才播 | 采用流式合成，边识别边合成边播放 |
| 游戏画面区域变化 | 识别区域失效 | 支持手动重新框选 + 自适应定位 |

## 8. 未来迭代规划

### Phase 2 — 体验优化

- 多种 TTS 音色可选（男女声、萝莉/御姐等）
- 可视化设置界面
- 识别区域热键调整
- 语音缓存：已生成的音频缓存复用，减少重复合成

### Phase 3 — 功能扩展

- 支持日语、英语、韩语配音
- 按角色匹配不同音色（从文字颜色/位置区分说话人）
- 语音播放历史回放
- 语音速度/音调自定义调节

### Phase 4 — 生态建设

- 社区音色包（用户自制 TTS 模型）
- 开放 API，允许其他游戏适配
- 移动端方案探索（安卓投屏 + 手机端播放）
